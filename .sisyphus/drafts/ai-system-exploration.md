## Requirements (confirmed)
- 사용자님은 `/Users/user01/Desktop/AI_system/[인트로 AI 자동화와 시스템 구축].md`와 `capture.md`를 기반으로 AI 시스템을 만들고자 함.
- 현재 목표, 범위, 구현 방식은 아직 정의되지 않음.
- 1차 목표 범위는 `capture.md`의 모델을 반영해 **전체 10개 팀 오케스트레이션**으로 결정됨.

## Technical Decisions
- 아직 확정된 기술 스택, 배포 방식, 운영 환경 없음.
- 문서 상에는 10개 팀/21개 에이전트 구성, 오케스트레이터-디렉터-리서치/토론/통합/품질 단계가 제시됨.
- 현재 저장소는 참조 문서 2개 외에는 실행 코드/구성 파일이 없어, 구현 전 단계의 기획형 문서 기반 작업 상태.
- 핵심 기술 접근: **오케스트레이터 기반 플랫 아키텍처**로 결정(Director/Coordinator 상위 제어 + 팀별 에이전트 플러그인 모델).
- 기본 실행 스택: **Node.js + TypeScript**(질문 결과 반영)
- TDD 도구: **bun test + vitest**(질문 결과 반영)

## Research Findings
- `.claude/memory/user-profile.md`에 따르면 사용자는 비개발자에 가까운 L2 수준으로, 비유 중심의 설명 선호.
- `capture.md`에는 AI 팀(마케팅, 재무, 교육, 상품 상세페이지, 사업개발 등) 조직도, 에이전트 역할 정의, 파이프라인, 출력물 구조(input/.generated/output), 단계별 검증 및 품질관리 흐름이 상세히 나열됨.
- `capture.md`에는 이미지 OCR 결과를 기반으로 한 표 형태 데이터가 다수 포함되어 있어 텍스트 품질이 불안정하고 오탈자/깨진 문맥이 존재함(모델이 OCR 기반인지 추정).
- 두 파일 모두 실제 실행 가능한 시스템 설계보다 비전 및 예시 흐름 중심이라, 실무 구현을 위해서는 우선 범위 축소와 우선순위 정리가 필요함.

## Open Questions
- 어떤 목표를 최우선으로 할지: 전체 10개 팀 동시 구축 여부를 확인했으나, 실제 1회 실행에서 동시 착수 범위는 `모든 팀(오케스트레이터+21 에이전트)` 구조를 기본안으로 설정
- 대상 사용자: **1인 창업자/소규모 팀**(초기 파일럿), 차후 조직 내부 운영팀 확장 예정
- 운영 제약: 예산, 인력, 사용 가능한 LLM API/클라우드 리소스
- 핵심 성공지표(우선순위): **ROI/비용 절감 우선**, 다음으로 처리속도·품질을 병행 평가
- 선호 워크플로우: 기존 노코드 우선, 아니면 코드 기반 자동화 우선
- 기본 우선순위: 1차 실행 시 **오케스트레이션/역할 계층 설계 + 팀별 MVP 워크플로우 동시 설계**
